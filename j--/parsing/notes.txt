[Problem 3 (For Statement)]

Goal: Add support for parsing for statements with our parser

Approach: Adding support for FOR statements required modifying and adding some new functions to the parser. 
Below I have changes laid out organized by function.
    - Added Functions:
        - forInit()
            - First we make an array to add all statements that will be returned.
              If we don't see a local variable declaration, then we parse a statement expressions
              followed by commas and succeeding statement expressions. Otherwise, we construct a JVariableDeclaration
              object, and add that object to our statement array. Once if statement is completed, we return the statements array.
        - forUpdate()
            - First, initialize the statements array. Then we parse at least one statement expression. Then while we can keep
              parsing commas, parse additional statement expressions and add them to our array list. Finally, return the statements array.
    - Modified Functions:
        - statement()
            - Declare the init and update array lists and assign them null values as these are optional for the FOR statement.
              Similarly, declare the condition expression to null as this is also optional. Then we parse a LPAREN character.
              Then parse an optional init using forInit, followed by a semi, followed by optional condition expression. Parse another
              semi, then an optional update using forUpdate, lastly followed by an RPAREN and then the body using statement().

[Problem 6 (Switch Statement)]

Goal: Add support for switch statements to our parser.

Approach: Similar to FOR statements, SWITCH statements involved modifying and adding a couple functions detailed below.

- Added Functions:
    - switchLabel()
        - If we parse a CASE token, parse an expression followed by a colon, then return the parsed expression.
          Otherwise, it means we have a DEFAULT token. Parse DEFAULT followed by a colon and return null.
    - switchBlockStatementGroup
        - Initialize array lists for blocks and labels. Parse one label using switchLabel and add it to array. While we see 
          CASE or DEFAULT tokens, parse additional labels using switchLabel and add it to array. Once labels have been parsed,
          we must parse block statements. While we don't see an RCURlY, CASE, or DEFAULT character that means
          there is a block statement to parse. Parse these statements and add them to the array list. Once everything was parsed,
          we call SwitchStatementGroup. If no blocks were parsed, pass in null for blocks. Otherwise we pass in the blocks array.
- Modified Functions:
    - statement()
        - Initialize array for switchStatementGroups. First parse a parExpression, followed by an LCURLY. While we don't
          see the RCURLY or EOF characters, parse the group and add it to array list using switchBlockStatementGroup.
          Then parse an RCURLY character. If no groups were parsed, call JSwitchStatement with null as input for groups,
          otherwise call the function with both the parsed parExpression and switchStatementGroups.
